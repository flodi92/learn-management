## Definition

The `RegExpTaskPresenter` guides the user through a sequence of regular-expression tasks in the console. For each task, it displays the regular expression and a shuffled selection of its positive and negative examples. When the task contains examples of both kinds, the selection includes at least one of each; the number shown is limited by the configured maximum. Examples are shown as they are, without surrounding delimiters. Characters that are invisible or easily overlooked are replaced by a highlighted (magenta) name in angle brackets, for example `<linebreak>`, `<tab>`, `<carriage return>` or `<space>`, and the empty string is shown as `<empty string>`. The replacement is done by `getExampleAlternative` in `regExp.taskPresenter.utils.ts`; the character names are defined in `regExp.taskPresenter.constants.ts`.

The user classifies every displayed example as positive (it matches) or negative (it does not match). Use **↑/↓** to move between examples; movement wraps from the last example to the first and vice versa. Use **←/→** to set the selected example to positive or negative, or press **p/n** to classify it and automatically move to the next example. The cursor also wraps when advancing with **p/n**.

Press **Enter** after classifying all examples to check the task. If any examples are still unclassified, the presenter asks the user to classify them first. Once checked, each example is shown in green if its classification is correct and red if it is incorrect. The presenter reports whether all answers were correct or some were wrong, and records the task result. If some answers were wrong, the presenter also checks the task descriptions linked by `confusedWith` of the current task description (looked up among all task descriptions the presenter was constructed with; ids without task description are ignored). A linked task description counts as confused with when an incorrectly answered example is positive for the current one and negative for the linked one, or vice versa. For each such linked task description, one line is shown underneath the report, naming the first such example, e.g. `xyzab is positive for /^xyz/ but negative for /xyz$/` or `abxyz is negative for /^xyz/ but positive for /xyz$/`. The detection is done by `determineConfusions` and the line is built by `getConfusionMessage`, both in `regExp.taskPresenter.utils.ts`. Press **Enter** again to continue to the next task.

After the final task, the presenter displays a summary of the number of correctly and incorrectly answered tasks, then signals that the presentation has finished. If started with no tasks, it reports that no tasks are available.

## Relationship to `TaskPresenter`

`RegExpTaskPresenter` extends `TaskPresenter` (see `src/userInterface/taskPresenter.md`), which provides the shared lifecycle: starting, the task sequence, the summary counters, the `onAnswered` and `onFinished` handlers and the `Result` built after each check. `RegExpTaskPresenter` is constructed with all task descriptions, which are used to look up the task descriptions linked by `confusedWith`.

`RegExpTaskPresenter` supplies the regular-expression specific parts: `start` additionally starts the console interaction (keypress handling) after the superclass has initialized the sequence. When a task description is loaded, the examples to show are selected and shuffled by `buildExamples` in `regExp.taskPresenter.utils.ts`. A task description counts as answered correctly when every example was classified correctly, and as confused with the ids of the linked task descriptions found by `determineConfusions`. After the last task, `finish` shows the summary, stops the console interaction and calls the registered `onFinished` handler. When started with an empty task list, it reports that there are no tasks and does not start the interaction.
